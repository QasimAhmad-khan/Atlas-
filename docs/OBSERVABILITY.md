# Observability

Data routes require a read or write bearer credential. Query latency spans include successful and failed SQL operations without SQL text or parameter values.

Run `python scripts/configure_local.py`, then `docker compose up --build --wait app worker prometheus collector tempo grafana`. Migrations are a separate dependency. Scale workers with `docker compose up -d --scale worker=3`. Docker DNS service discovery scrapes every replica; workers get unique IDs. Access Grafana on localhost:3000 with admin and the generated password in `.env`. Metrics, database and Grafana ports are local only. The collector and Tempo expose no host port.

`/internal/metrics` requires a separate bearer secret. The public ALB must deny `/internal/*`. Each API replica exports HTTP/DB metrics; each worker exports retries, throughput and recoveries. Queue/heartbeat gauges queried by API replicas describe shared state; use **max**, not sum, across replicas. Counters describe process observations, can reset on restart, and are not a durable audit ledger. No URL, domain, job ID, worker ID or credential is a metric label. DB labels use only four DML operations and OTHER.

Submit an authenticated crawl and save `X-Request-ID` and `X-Trace-ID`. Search Tempo for the trace ID and JSON logs for that ID. W3C context is stored on `crawl_jobs`, loaded into each lease and continued by `crawl.process` and `crawl.persist`. Old jobs without context start independent worker traces. Spans do not record SQL values, URLs, exception messages or credentials. Structured logs include timestamp, severity, service, environment, release, request_id, trace_id, job_id, worker_id, event and duration. Request completion duration is seconds.

The provisioned dashboard covers HTTP latency/errors, queue states and age, worker health/throughput, retries/exhaustion/recovery, query latency/errors/pool use and memory. A stale heartbeat counts as a failed worker only while it owns leases; recovery clears that gauge. Heartbeats continue during fetches, while progress freshness detects a live worker stalled with leases. Successful graceful exit deletes its heartbeat. Failed exporters do not crash jobs; remote telemetry outages can lose spans after the bounded exporter buffer fills.

Alert rules cover DB outages, no healthy workers, failed/stalled workers, aging backlog, API errors and missing scrape targets. `promtool test rules observability/alerts.test.yml` exercises a synthetic DB failure and recovery. This is rule verification, not evidence of a running Grafana alert notification. Configure a notification receiver for your actual operational environment before claiming paging.

Verification: PostgreSQL API → queue → worker → persistence trace continuity is exercised by `tests/integration/test_tracing.py`. Authentication and bounded labels are covered by API tests. Native Windows Grafana 12.2.1 and Prometheus 3.5.0 were run against the real API and worker, with the repository dashboard provisioned unchanged apart from readable units/legends. Both authenticated scrape targets were up. Actual screenshots and API evidence are in `artifacts/observability/`; a separate ten-second k6 burst supplied read traffic. Five-minute rate windows smooth that burst; these charts are not the final performance benchmark.

The temporary Grafana listener and Prometheus listener used localhost ports 53000 and 59090; anonymous Viewer access was enabled only for that local capture. The generated admin credential and scrape token are not in the artifacts. Docker is unavailable, so full Compose networking, collector/Tempo export, Linux process-memory collection and notification delivery remain unverified. Windows lacks Prometheus's Linux process-memory metric; memory evidence instead uses the actual process working-set samples in the performance report. Empty worker outcome series reflect an idle worker, not a failed exporter. No dashboard screenshots have been manufactured.
